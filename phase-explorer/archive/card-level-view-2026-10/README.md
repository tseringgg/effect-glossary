# Archived card-level view (2026-10)

**Archived card-level view. Numbers here do not match the current view.**

This is the browse / ledger / parse-audit experience as it stood on 2026-10-06, before the per-ability
taxonomy became the main view. It is a byte copy of what the pages read, kept so the old view can be opened
and compared. Nothing here is regenerated by the current build.

## Final numbers of the old view

| | |
|---|---:|
| universe (oracle ids in the ledger) | 38,921 |
| not cards (tokens, art cards, emblems, planes, schemes, vanguards, ...) | 4,057 |
| in scope | 34,864 |
| **placed ("organized")** | **26,085 (74.8% of in scope; 67.0% of the universe)** |
| **Not yet organized** | **8,779** |
| **leaves (card-level clustering)** | **657** (66 branches, 28 in sectors) |

How the 26,085 break down: clustered 21,788, nearby (proximity) 1,303, keyword block 1,262, ability-placed
1,172 (716 clean + 456 gap cards), "No abilities" 351, replacement-effect groups 209.
Not yet organized: gap 5,252, no close group 3,459, no effect to group 31, not parsed 29, known parse mistake 8.
Snapshot: phase.rs card-data.json, last modified 2026-04-20, plus the post-snapshot overlays in `data/overlay/`.

## Open it

```
python src/serve.py 8766        # run from THIS directory; serves it as the root
# then http://localhost:8766/reports/browse.html   (also ledger.html, card-explorer.html)
```

The pages fetch `../build/...`, which resolves inside this archive. Every page carries the banner above. Port
8766 avoids clashing with the live viewer on 8765.

## What is in here

| path | what |
|---|---|
| `reports/` | the four pages (with banner), `cardview.js`, `branchmap.js`, `findcard.js`, and the reports they link |
| `build/` | every file the pages fetch (`index.json`, `chunks/`, `clusters.json`, `branches.json`, `placements.json`, `unorganized*.json`, `lookup.json`, the layer files, the two ledgers, ...) |
| `corrections/`, `data/overlay/` | inputs the generators read (hand corrections, collision-recovered and new-release overlays) |
| `src/` | every generator of the old view, unmodified |
| `docs/` | the project docs as of this date (README, KNOWN_LIMITATIONS, SCHEMA, DECISIONS, PROVENANCE, NAME_COLLISIONS) |
| `MANIFEST.sha256` | live-before, live-after and archived hash of every file |

Not copied (large inputs, unchanged in the live tree): `data/card-data.json` (83 MB, sha256 in `docs/PROVENANCE.md`
terms), the MTGJSON and Scryfall dumps. `build/` is ignored by git under the existing `.gitignore` rule, so the build
copies stay local; the generators can recreate them.

## Byte identity

Every file is a byte copy, **except the four HTML pages**, which have one banner `<div>` inserted right after
`<body>`. For those, `MANIFEST.sha256` lists the live hash and the archived hash, and removing the exact banner
string from the archived page reproduces the live hash (checked when the archive was made).

## Run order to rebuild the old view (from the live tree's inputs)

```
python src/build_index.py            # -> build/index.json, facets.json, meta.json, chunks/
python src/build_collisions.py       # -> NAME_COLLISIONS.md, build/collisions.json
python src/cluster_structural.py     # -> build/clusters.json, reports/clustering-structural.md   (needs hdbscan, numpy, scipy)
python src/branch_leaves.py          # -> build/branches.json, reports/branches.md
python src/sub_branches.py           # -> build/sub_branches.json (report only)
python src/build_sectors.py          # -> build/sectors.json
python src/audit_leaf_types.py       # -> build/type_audit.json
python src/leaf_phrases.py           # -> build/leaf_phrases.json
python src/match_spans.py            # -> build/match_spans.json, build/effect_anchors.json
python src/build_images.py           # -> build/card_images.json  (downloads from Scryfall)
python src/build_ledger.py           # -> build/ledger.json
python src/recover_dropped.py        # -> data/overlay/recovered-cards.json  (needs oracle-gen)
python src/add_new_release_cards.py  # -> data/overlay/new-release-cards.json (needs oracle-gen)
python src/build_placements.py       # -> build/placements.json
python src/build_keyword_layer.py    # -> build/keyword_layer.json
python src/build_ledger.py           # again
python src/detect_condition_drops.py # -> build/condition_drops.json
python src/build_also_fits.py        # -> build/also_fits.json
python src/build_keyword_layer.py    # again (recovered keyword-only cards)
python src/build_partial_ability_layer.py  # -> build/partial_ability_layer.json
python src/build_signature_layer.py  # -> build/signature_layer.json
python src/build_ability_layer.py    # -> build/ability_layer.json, build/ability_ledger.json
python src/build_ledger.py           # again
python src/build_unorganized.py      # -> build/unorganized.json, unorganized_cards.json, lookup.json
python src/serve.py
```

The ledger runs more than once because placement reads the ledger's statuses and the ledger then records placement.
Overlay scripts (`apply_*_overlay.py`) were one-time corrections to `data/overlay/`; their outputs are in this archive.
