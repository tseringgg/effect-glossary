Parse quality of the current result set, not the whole corpus. clean = no Unimplemented/GenericEffect nodes · partial = real structure plus at least one such node · unparsed = has oracle text but zero structured abilities · vanilla = no oracle text at all. Quality is computed from gap nodes only — not from parse_warnings, for the reason in the header.
+ unmodelled node is a separate, overlapping axis, not a fifth quality: an enum slot the parser left unmodelled rather than an effect it failed to build — a {"Unknown": "<raw text>"} trigger mode, or an Unrecognized condition. 887 entries labelled clean carry one (1,288 total), so clean means "no Unimplemented/GenericEffect node", not "fully modelled". Filter on it to see what the clean/partial split misses.
⚠ has correction is our own hand-maintained overlay (corrections.json), separate again from both signals above: cards where we found and evidenced a real defect that phase.rs's clean label, parse_warnings, and gap nodes all missed. See corrections/SCHEMA.md.
Filters are slot-aware: each axis matches only nodes found in that slot, so quantity:Fixed (35,139 nodes) and cost:Fixed (198 nodes) are different filters and never collapse into one. Option lists are derived from the data at build time, so they track phase.rs's parser instead of drifting from a hardcoded list.
